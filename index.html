The problem

Stellar's Confidential Token design keeps transaction amounts and balances private while preserving the compliance surface area: addresses stay visible, and the protocol preview already exposes policy contracts, allow/block-list identity registries, account freezing, SAC passthrough and auditor functionality.

What is missing is the layer between those primitives and an actual deployment. Every issuer that needs allowlists, sanctions screening and jurisdiction rules ends up writing the same rule engine, the same versioning scheme and the same decision semantics — usually without anyone able to show that two implementations agree on a contested case.

Three repositories, one pipeline

Strict separation of duties. The dependency chain is one-way and versioned.

Define

safeguard-policy

The policy model, versioned rule primitives, on-chain registries and a deterministic APPROVE/BLOCK/FLAG engine with a documented precedence order.

Enforce

safeguard-hooks

A fail-closed Soroban compliance-hooks contract that gates all six confidential-token operations, with admin-gated freeze administration and optional SAC passthrough.

Verify

safeguard-audit

Append-only audit records with chained integrity digests, authorization, investigation, evidence packages and reproducible reports.

Why it is different

Fail closed, everywhere

Missing information never silently approves. An unknown account status flags. An unknown jurisdiction takes the rule's action. An unreachable policy contract denies. Unbound tokens deny.

Precedence pinned by tests

Two implementations of the same policy cannot disagree about a contested case, because the evaluation order is documented and enforced by property tests rather than left to interpretation.

Codes that never move

Reason codes and contract error codes are assign-only. A code quoted in a stored record, a log line or an incident never shifts meaning, because removed variants keep their number.

Documented cost

Every public contract function is measured in stroops and published. Enforcement gates short-circuit, so a denial is cheaper than an approval.

Quickstart

# 1. Define — evaluate a policy locally, no network needed
git clone https://github.com/Safeguard-Inc/safeguard-policy
cd safeguard-policy && cargo test --workspace

# 2. Enforce — build the contract that gates token operations
git clone https://github.com/Safeguard-Inc/safeguard-hooks
cd safeguard-hooks && cargo build --release --target wasm32v1-none -p compliance-hooks

# 3. Verify — record and verify what actually happened
git clone https://github.com/Safeguard-Inc/safeguard-audit
cd safeguard-audit && cargo test --workspace
