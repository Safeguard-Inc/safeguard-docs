What was verified

  • schema_version returns 1 on the policy contract.
  • admin returns the configured admin public key.
  • is_authorized(account, token) answers false for a token that is not bound to an active policy — the fail-closed posture, observed rather than assumed.
  • register_version, activate_version and bind_token each succeeded against the ledger and emitted their events (policy_created, rule_registered, policy_activated, token_bound).
  • The hooks contract was initialized, configured against the policy contract above, and had its token bound.
  • Freeze and unfreeze were exercised for real on the bound token and both succeeded against the ledger.

Reproduce it

# Policy contract — deploy, initialize, register and activate the default policy
git clone https://github.com/Safeguard-Inc/safeguard-policy
cd safeguard-policy
stellar keys generate safeguard-admin --network testnet --fund
STELLAR_ADMIN=safeguard-admin bash scripts/deploy-testnet.sh --load-policy

# Hooks contract — deploy, initialize, configure against the policy, bind a token
git clone https://github.com/Safeguard-Inc/safeguard-hooks
cd safeguard-hooks
safeguard-hooks --config deployments/testnet/configuration.json --source safeguard-admin \
  deploy --hooks-wasm target/wasm32v1-none/release/compliance_hooks.wasm \
         --policy-id <policy-contract-id> --save

Confidential Tokens on Stellar are a developer preview. Treat this deployment as a rehearsal rather than production.
