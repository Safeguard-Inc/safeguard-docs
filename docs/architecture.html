System design & data flow

Four-tier architecture

Safeguard is organized into four purpose-built repositories. Each boundary is versioned, strictly typed, and independently tested with 10-check automated CI/CD.

The decision engine

Every evaluation resolves to exactly one of APPROVE, BLOCK or FLAG. The checks run in a fixed, documented order and the first decisive outcome wins — later checks never run.

OrderGateDecisive when
1Account status (structural)frozen or suspended → BLOCK; restricted or unknown → FLAG
2Allowlistrequired but not a member
3Denylistsubject is listed
4Sanctionsscreening produced a match
5Jurisdictionregion is restricted, prohibited or unknown
6Spend Capamount > cap → FLAG / ESCROW
7otherwiseAPPROVE with no_reason

Fail-closed posture

Missing information or unexpected state never silently approves.

SituationResult
Unknown account statusFLAG account_status_unknown
Unknown jurisdictionthe rule's action — BLOCK under a blocking rule
